`code-review` review un changement contre la requête, le plan, la spec ou une issue GitHub optionnelle, plus les standards du repo. Ça ne remplace pas `verify`.

## Invoquer

```bash
$code-review issue 123 since origin/main
```

## Ce qu'il fait

- Deux verdicts : Spec (on a construit la bonne chose) et Standards (le code est acceptable).
- S'arrête avant la preuve runtime. Ça, c'est `verify`.
- Étape de revue dans `oneshot`, ou passe standalone.
