Les skills sont des workflows réutilisables que Claude Code et Codex peuvent
invoquer. AIBlueprint installe le lot gratuit dans le dossier partagé
`~/.agents/skills`.

## Workflow de fonctionnalité principal

Choisis un workflow selon la tâche :

- **`apex`** est inclus dans le lot gratuit. Il lance une boucle adaptative Analyze → Plan → Execute → eXamine avec checkpoints reprenables, revue fondée sur le risque, et validation.
- **`oneshot`** est un routeur Premium qui exécute `analyze → plan → implement → code-review → verify` dans l'ordre.

Utilise `apex -a -x` pour une implémentation peu interactive avec revue
adversariale, ou `oneshot -a` pour la séquence fixe complète. OneShot utilise
le plan d'implémentation comme source de vérité ; une issue GitHub est
optionnelle pour un travail ciblé.

Voir [Workflow principal](/core-workflow) pour la responsabilité des étapes
et l'invocation directe des skills, puis [Workflows avancés](/advanced) pour
les flags Apex et OneShot, l'automatisation, et la vérification persistante
adossée à des screenshots.

## Utilitaires manuels

Ces skills de maintenance divers ne tournent que quand tu les invoques
explicitement. Claude et Codex sont tous les deux configurés pour empêcher
la sélection implicite.

| Skill | Commande | Objectif |
| ----- | ------- | ------- |
| `audit-memories` | `$audit-memories` | Auditer ou nettoyer la doc projet destinée aux agents contre la vérité actuelle du projet. |
| `audit-skills` | `$audit-skills` | Auditer l'usage observé des skills, la découverte de doublons, les contrôles d'invocation, et le scope global versus projet. |

## Skills Premium

[Configuration Premium](/commands/pro-setup) ajoute le workflow principal
(`analyze`, `plan`, `implement`, `code-review`, `verify` et `oneshot`) et des
skills supplémentaires comme `impeccable`, `better`, `animate` et
`use-artifacts`.

Le catalogue installé dépend de ton lot et de ta version. Utilise le
sélecteur de skills de l'assistant pour inspecter les skills disponibles
après le setup.

## Comment les skills sont organisés

Chaque skill est un dossier qui contient un fichier `SKILL.md`, et souvent
un dossier `references/` avec des guides complémentaires. Comme ils vivent
dans `~/.agents/skills`, chaque outil lié partage les mêmes skills.

## Installation

Les skills sont installés par [agents setup](/commands/agents-setup).
Utilise [agents unify](/commands/unify) pour centraliser dans `~/.agents` les
skills globaux que tu as déjà, ou `agents unify projects` pour déplacer les
skills locaux au projet dans le dossier `.agents/skills` de ce dépôt.

Voir [Utiliser un style](/concepts/use-style) pour le système visuel,
[Utiliser des artefacts](/concepts/use-artifacts) pour les expériences HTML
locales réutilisables, [Ne pas overflow la mémoire](/concepts/dont-overflow-memory)
pour garder la mémoire d'agent courte, et [Exemples](/examples) pour le
sélecteur de styles live.
